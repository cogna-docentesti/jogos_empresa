1. Visão Geral da Arquitetura 
O jogo roda localmente no dispositivo Android do aluno (Unity - APK). O estado da partida e 
persistido em SQLite no próprio dispositivo - o que garante funcionamento sem internet, essencial 
em contexto de sala de aula. Ao detectar conexão disponível, os dados são sincronizados com o 
Firebase, que serve como banco central para o painel do professor e como base escalável para 
versões futuras com múltiplas turmas e instituições. 
 
Decisão de escala: Firebase foi escolhido por suportar crescimento sem mudança de arquitetura. O 
plano gratuito (Spark) cobre a fase de pesquisa. O plano pago (Blaze, pay -as-you-go) habilita escala 
para qualquer número de alunos e instituições sem reescrita de código ou migração de banco.

Arquitetura do jogo 
A arquitetura adotada separa claramente dois contextos:  
• Dentro do jogo ( síncrono,  local): os sistemas se comúnicam via C# Events (EventBus). 
RoundManager dispara um evento, FinancialEngine calcula, UIManager atualiza a tela. Tudo 
local, sem rede. 
• Com o Firebase (as síncrono, background): ao encerrar uma rodada, o SDK Firebase 
enfileira a gravação e executa quando há internet, sem interromper o jogo.

5. Banco de Dados Local: SQLite 
O SQLite e o banco de dados embarcado padrão para aplicativos Android. Roda diretamente no 
dispositivo sem servidor, sem conexão e sem configur ação. E a fonte de verdade durante o jogo - 
qualquer falha de rede não afeta o progresso do aluno.  
 
C# - Inicialização SQLite (sqlite-net-pcl) 
// Inicialização na primeira abertura do app: 
string dbPath = Path.Combine(Application.persistentDataPath, "game.db"); 
// Android resolve para: /data/data/com.cogna.restaurantgame/files/game.db 
 
var db = new SQLiteConnection(dbPath); 
db.CreateTable<PlayerProfile>(); 
db.CreateTable<GameSession>(); 
db.CreateTable<RoundResult>(); 
db.CreateTable<FinalReport>(); 
 
// Indices para consultas do dashboard: 
db.Execute("CREATE INDEX IF NOT EXISTS idx_round_session ON 
RoundResult(sessionId)"); 
db.Execute("CREATE INDEX IF NOT EXISTS idx_session_user  ON 
GameSession(userId)");

6. Banco de Dados em Nuvem: Firebase 
O Firebase Firestore e um banco NoSQL orientado a documentos, gerenciado pelo Google. Não 
requer servidor próprio, não requer configur ação de infraestrutura e escala automaticamente com o 
crescimento do projeto.  
 
Plano gratuito (Spark): suficiente para a fase de pesquisa. Plano pago (Blaze, pay -as-you-go): escala 
para qualquer número de alunos e instituições sem alteração de arquitetura ou migr ação de dados.

6.2 Segurança - Firestore Security Rules 
As regras de segurança garantem que cada aluno só leia e escreva as próprias sessões, e que o 
professor acesse apenas os dados do seu curso. Nenhum dado entre cursos fica exposto.  
Firestore Security Rules 

PAGE 15
 
Público 
rules_version = '2'; 
service cloud.firestore { 
  match /databases/{db}/documents { 
 
    // Aluno acessa apenas o proprio perfil 
    match /students/{userId} { 
      allow read, write: if request.auth.uid == userId; 
    } 
 
    // Aluno escreve apenas as proprias sessoes 
    match /sessions/{sessionId} { 
      allow write: if request.auth.uid == resource.data.userId;  
      allow read:  if request.auth.uid == resource.data.userId  
                   || request.auth.uid == resource.data.professorId; 
    } 
 
    // Professor le todas as sessoes do seu curso 
    match /sessions/{sessionId} { 
      allow read: if request.auth.uid == resource.data.professorId;  
    } 
  } 
}

7.2 Offline-First 
O jogo foi projetado para operar completamente sem internet. O progresso do aluno nunca 
depende de conexão de rede. 
• Durante o jogo: toda a lógica roda localmente no Unity. SQLite e a fonte de verdade.  
• Sincronização: ao detectar conexão, o Firebase SDK envia os dados em background. Se 
não houver internet na ses são inteira, os dados ficam no SQLite e são sincronizados na 
próxima oportunidade. 
• Fallback manual: em casos extremos (aluno nunca teve internet), o arquivo SQLite pode 
ser exportado e importado pelo professor via ferramenta administrativa.  
 
7.3 Distribuição do APK 
• Fase de pesquisa: link direto para download do .apk via Firebase Hosting ou Google Drive.

• Conta de desenvolvedor: USD 25 taxa única.

8.2 GameManager (Singleton persistente)  
C# - GameManager 
public class GameManager : MonoBehaviour { 
    public static GameManager Instance { get; private set; } 
    public PlayerState  CurrentState  { get; private set; } 
    public IRepository  Repository    { get; private set; } 
 
    void Awake() { 
        if (Instance != null) { Destroy(gameObject); return; } 
        Instance = this; 
        DontDestroyOnLoad(gameObject); 
        // v1: salva local + sincroniza Firebase quando ha internet 
        Repository = new CompositeRepository( 
            new LocalRepository(), 
            new CloudRepository() 
        ); 
    } 
}

8.3 EventBus (Observer Pattern)  
O EventBus desacopla completamente os sistemas. O RoundManager não precisa conhecer o 
UIManager nem o CloudSync - ele dispara um evento C# e qualquer sistema que precisar reage 
de forma independente.  
C# - EventBus 
public static class EventBus { 
    public static event Action<RoundResult>   OnRoundCompleted; 
    public static event Action<EventData>     OnRandomEventTriggered; 
    public static event Action<float>         OnCashUpdated; 
    public static event Action<int>           OnReputationChanged;  
    public static event Action                OnBankruptcy; 
    public static event Action<FinalReport>   OnGameCompleted; 
    public static event Action<PlayerState>   OnConfigurationCompleted;  
}

            LoanPayment = loan, ThirteenthSalary = thirteenth,

            OpeningCash = state.CurrentCash, 
            ClosingCash = state.CurrentCash + netResult 
        }; 
    } 
}

C# - Sincronização offline-first 
// Ao encerrar uma rodada (chamado pelo RoundManager): 
async void OnRoundEnd(RoundResult result) { 
    // 1. Salva local - não depende de internet, sempre funciona 
    await GameManager.Instance.Repository.SaveRoundResultAsync(result);  
 
    // 2. Atualiza o estado em memoria 
    GameManager.Instance.CurrentState.ApplyRoundResult(result); 
 
    // 3. EventBus notifica UIManager, AudioManager etc. 
    EventBus.OnRoundCompleted?.Invoke(result); 
} 
 
// CompositeRepository - salva local e tenta cloud em background: 
public async Task SaveRoundResultAsync(RoundResult r) { 
    await _local.SaveRoundResultAsync(r);    // sempre 
    _ = _cloud.SaveRoundResultAsync(r);       // fire-and-forget 
    // Firebase SDK enfileira se offline; reenvio automatico 
}

10. Fluxo de Estado (State Machine) 
O SceneController gerencia o fluxo de naveg ação entre cenas Unity como uma State Machine 
finita. Transições invalidas são bloqueadas em código - por exemplo, e impossível acessar o 
GameLoop sem ter concluído as 6 etapas de configuração. 
 
C# - Enum de estados GameState 
public enum GameState { 
    Bootstrap,            // verifica save existente; carrega ScriptableObjects 
    MainMenu,             // nova partida | continuar | configuracoes 
    Config_City,          // etapa 1/6 de configuração 
    Config_Restaurant,    // etapa 2/6 
    Config_Location,      // etapa 3/6 - PERMANENTE 
    Config_Equipment,     // etapa 4/6 
    Config_Team,          // etapa 5/6 
    Config_Capital,       // etapa 6/6 - apos conhecer todos os custos 
    BMC_Review,           // canvas gerado automaticamente; aluno visualiza 
    Round_Start,          // inicio da rodada - verifica condicao de falencia 
    Round_Sales,          // FinancialEngine.Calculate() 
    Round_Costs,          // debita custos fixos e parcelas 
    Round_Event,          // EventSystem.DrawEvent() + escolha do aluno  
    Round_Summary,        // exibe DRE mensal e historico de caixa  
    FinalReport,          // rodada 12 concluida - gera DRE anual 
    GameOver_Bankruptcy,  // caixa negativo por 3 rodadas consecutivas 
}

11. Escalabilidade e Roadmap 
11.1 Princípios de extensão 
A arquitetura foi projetada para que adicionar conteúdo e funcionalidades não exija refatorar o que 
já existe. 
• Cidades, restaurantes, localizações , equipamentos e eventos: ScriptableObjects - criar 
um novo asset no Unity Editor e suficiente, sem tocar em código. 
• Novos eventos: adicionar um EventData ao EventDatabase com peso e opções. O 
EventSystem sorteia automaticamente. 
• CoherenceMatrix: lookup table em JSON - ajustar regras de coerência sem compilar. 
• Novos backends: implementar IRepository. O GameManager não sabe qual 
implementação está usando. 
• Novos módulos (competição , franquias): registrar via interface IGameModule. O 
GameManager carrega os módulos disponíveis por injeção de dependência.
