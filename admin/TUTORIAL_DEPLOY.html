Publicar o Admin em um servidor gratuito

Passo a passo para colocar a pasta admin/ no ar usando o plano gratuito do Render, com os dados salvos no próprio repositório GitHub do jogo.

0. Visão geral

Por que Render + GitHub?

O plano gratuito do Render roda um servidor Node.js sem pedir cartão de crédito, mas apaga o disco sempre que o serviço reinicia ou "dorme" por falta de acesso. Se o admin salvasse o JSON no disco do Render, os cadastros sumiriam.

Por isso, no servidor, o admin usa STORAGE=github: cada "Salvar" vira um commit no arquivo admin-data/events.json do repositório. Os dados ficam guardados, com histórico, e já no lugar onde o importador do Unity procura.

Repositório de organização

O repositório pertence à organização cogna-docentesti. Duas permissões podem depender de um administrador da organização: (1) liberar o aplicativo do Render para ler o repositório e (2) aprovar o token do passo 4. Se isso travar, crie um repositório pessoal só para o admin (copie as pastas admin/ e admin-data/) e siga o mesmo tutorial trocando o nome do repositório.

2. Testar no computador

Antes de publicar, confirme que o admin roda localmente. No PowerShell:

cd C:\Users\elisa\Projects\jogos_empresa\admin
npm install
Copy-Item .env.example .env
npm run dev
  1. Abra .env e defina ADMIN_PASSWORD com uma senha de teste. Mantenha STORAGE=file.
  2. Acesse http://localhost:3000. O navegador pede usuário (admin) e a senha.
  3. Edite qualquer evento e clique em Salvar (ou Ctrl + S).
  4. Confira que jogos_empresa\admin-data\events.json mudou (git diff admin-data).
  5. Pare o servidor com Ctrl + C.
O que é o arquivo .env?

Um arquivo de texto com configurações e segredos (senha, token). Ele está no .gitignore e nunca deve ir para o GitHub. No Render, os mesmos valores são cadastrados na tela do serviço (passo 5).

3. Enviar o código ao GitHub

O Render publica a partir de uma branch do GitHub. Envie as pastas admin/ e admin-data/:

cd C:\Users\elisa\Projects\jogos_empresa
git add admin admin-data
git commit -m "feat: painel admin de eventos"
git push

Depois, faça o merge na main pelo Pull Request, como no fluxo normal do projeto. Este tutorial considera a main como branch publicada e como branch onde os dados são gravados.

Confira antes do commit

Rode git status e verifique que admin/node_modules e admin/.env não aparecem na lista.

4. Criar o token do GitHub

O admin precisa de uma chave para gravar no repositório. Use um token fine-grained, limitado a um único repositório e a uma única permissão.

  1. No GitHub, clique na sua foto (canto superior direito) e em Settings.
  2. No menu lateral, no final: Developer settings > Personal access tokens > Fine-grained tokens.
  3. Clique em Generate new token e preencha:
    Token name
    admin-jogos-empresa
    Expiration
    90 dias (anote a data para renovar)
    Resource owner
    cogna-docentesti
    Repository access
    Only select repositories > jogos_empresa
    Permissions
    Contents: Read and write
  4. Clique em Generate token e copie o valor que começa com github_pat_. Ele só aparece uma vez.
O que a permissão "Contents" libera?

Ler e gravar arquivos do repositório (é o que gera os commits). Ela não permite apagar o repositório, mudar configurações ou acessar outros repositórios. A permissão Metadata: Read-only é adicionada automaticamente pelo GitHub.

Token "pending"

Se a organização exigir aprovação, o token fica como pending até um administrador aprovar. Enquanto isso, o admin publicado mostra erro 403 ou 404 ao carregar os eventos.

5. Criar o serviço no Render

  1. Entre em dashboard.render.com, clique em + New e escolha Web Service.
  2. Em Git Provider, selecione o repositório jogos_empresa. Se ele não aparecer, clique em Configure GitHub e libere o acesso do Render à organização.
  3. Preencha a configuração exatamente assim:
    Name
    admin-jogos-empresa (vira parte do endereço)
    Language
    Node
    Branch
    main
    Region
    a mais próxima disponível (ex.: Virginia)
    Root Directory
    admin
    Build Command
    npm install
    Start Command
    npm start
    Instance Type
    Free
  4. Em Environment Variables, clique em Add Environment Variable para cada linha:
    NAMEVALUE
    STORAGEgithub
    ADMIN_USERadmin (ou outro nome)
    ADMIN_PASSWORDuma senha forte, diferente da senha de teste
    GITHUB_TOKENo token github_pat_... do passo 4
    GITHUB_REPOcogna-docentesti/jogos_empresa
    GITHUB_BRANCHmain
    GITHUB_DATA_DIRadmin-data
  5. Abra Advanced e em Health Check Path informe /healthz.
  6. Clique em Deploy Web Service. Acompanhe a aba Logs até aparecer: 
    Admin rodando em http://localhost:10000
Armazenamento: github -> cogna-docentesti/jogos_empresa@main/admin-data
    O "localhost:10000" é interno do Render; o endereço público aparece no topo da página do serviço.
Por que "Root Directory = admin"?

O repositório é o projeto Unity inteiro. O Root Directory diz ao Render para instalar e rodar apenas a pasta admin. Ele também faz o Render ignorar commits fora dessa pasta: os commits que o admin grava em admin-data/ não disparam um novo deploy.

Sem senha, o serviço não sobe

Com STORAGE=github, o admin se recusa a iniciar se ADMIN_PASSWORD estiver vazio. Isso evita publicar um painel aberto que escreve no repositório.

6. Acessar e conferir

  1. Abra o endereço mostrado pelo Render, no formato https://admin-jogos-empresa.onrender.com.
  2. Informe o usuário e a senha definidos em ADMIN_USER e ADMIN_PASSWORD.
  3. No rodapé do menu lateral deve aparecer Dados salvos em GitHub.
  4. Altere um detalhe de um evento, salve e abra o repositório no GitHub: em Commits aparece admin: atualiza evento <id>.
Compartilhar com a equipe

Envie o endereço e o login para quem vai cadastrar. Todos editam o mesmo arquivo. Salvamentos simultâneos em eventos diferentes são aplicados em sequência; se duas pessoas editarem o mesmo evento ao mesmo tempo, vale o último salvamento.

7. Levar os dados ao Unity

Uma única vez: copie admin/unity/EventJsonImporter.cs para Assets/Editor/Events/EventJsonImporter.cs e aguarde o Unity compilar.

Sempre que houver cadastros novos:

  1. No terminal, na pasta do projeto: git pull.
  2. No Unity: Tools > Jogo > Eventos > Importar JSON do Admin.
  3. Leia a janela de resumo (criados, atualizados, removidos). Se algum evento foi excluído no admin, o Unity pergunta se o asset deve ser apagado.
  4. Faça commit dos .asset alterados em Assets/Resources/Events.
Não use mais o gerador antigo

O menu Gerar ou atualizar eventos reescreve os 20 eventos com os valores fixos do EventAssetGenerator.cs e desfaz o que foi cadastrado no admin.

8. Limites do plano gratuito

LimiteEfeito no admin
Serviço "dorme" após 15 minutos sem acessoO primeiro acesso depois disso demora cerca de 1 minuto. Os acessos seguintes são normais.
750 horas de instância por mêsSuficiente para um serviço ligado o mês inteiro. Se passar, o serviço fica suspenso até o mês seguinte.
Disco apagado ao reiniciarSem efeito: os dados ficam no GitHub.
Token com validadeQuando o token expirar, gere outro (passo 4) e atualize GITHUB_TOKEN em Environment no Render.

Os limites podem mudar. Consulte render.com/docs/free.
